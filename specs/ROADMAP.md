# Product and Content Expansion Roadmap

The roadmap is intentionally evidence-gated. Phase numbers define direction, not a commitment to publish every listed page.

## Phase 1 — Prove two wedges

### Workspace

Core graph:

`monitor(s) → desk width/depth → chair/room clearance`

Initial page families:

- desk size for monitor configurations;
- reverse-fit pages for common desk widths;
- monitor physical-size comparisons;
- desk depth;
- chair clearance;
- workspace FitCheck hub.

### Bedroom

Core graph:

`bed → room → clearance → nightstand/dresser/wardrobe`

Initial page families:

- minimum room size by bed;
- reverse-fit common room sizes;
- clearance around bed;
- bed + nightstand configurations;
- market-specific bed-size reference;
- bedroom FitCheck hub.

### Phase 1 success signal

After launch, at least one cluster shows repeated organic impressions/query patterns across multiple related pages. Expansion should follow the winning cluster rather than splitting effort evenly forever.

## Phase 2 — Deepen winning graph

### Workspace expansions

- monitor + laptop;
- monitor + speakers;
- PC case placement;
- printer footprint;
- standing desk clearances;
- two-desk office layouts;
- desk-to-wall and chair movement clearance;
- ultrawide configurations.

### Bedroom expansions

- dresser drawer-opening clearance;
- wardrobe door/sliding-door clearance;
- bedside table size/spacing;
- rug sizing as a supporting relationship;
- complete room layout matrices;
- more market-specific sizing only when clearly labeled.

### Phase 2 publishing rule

Use Search Console evidence to select dedicated URLs. Keep weak permutations inside matrices/hubs.

## Phase 3 — Adjacent rooms

### Dining

Graph:

`table → chairs → room → walkway → rug/sideboard`

High-value page types:

- what table fits my room;
- room size for 4/6/8-person tables;
- chair pull-out clearance;
- round vs rectangular space use;
- narrow-room table selection.

### Living room

Graph:

`sofa → coffee table → TV → rug → walkway`

High-value page types:

- sofa size for room;
- sofa ↔ TV distance;
- sofa ↔ coffee-table clearance;
- sectional room requirements;
- living-room arrangement matrices.

### TV

Focus on decision/fit pages, not commodity dimension pages:

- TV size for wall width;
- TV size for viewing distance;
- TV stand width by TV size;
- TV + stand + room relationship.

## Phase 4 — Purchase/delivery fit

### Appliances

Graph:

`appliance → cabinet/closet/opening → ventilation/connection clearance`

Candidates:

- washer/dryer closet requirements;
- refrigerator cabinet clearance;
- dishwasher opening size;
- oven/microwave openings;
- appliance through-door fit.

### Furniture delivery

Graph:

`object → door → hallway → turn → stair/landing → final room`

Do not build a full 3D mover in the first iteration. Begin with high-confidence 2D/orthogonal clearance scenarios, and label limitations clearly.

## Phase 5 — Specialist extensions

### Storage/shelving

- shelf depth by object type;
- wardrobe depth for hangers;
- storage-box ↔ shelf fit;
- printer/cabinet fit;
- vinyl/book/shoe spacing.

### Home gym

- treadmill operating space;
- power-rack room/ceiling clearance;
- rowing machine footprint;
- multi-equipment room planning.

### Garage/vehicles

Potentially large but data-heavy. Enter only when there is a sustainable model for current vehicle dimensions and market/version differences.

## Expansion scoring

Before a new cluster receives substantial work, score it on:

- demonstrated query/impression demand;
- weakness of existing answer quality;
- number of legitimate independent page intents;
- structured-data/template reuse;
- evergreen/stability profile;
- internal-link adjacency to existing graph;
- data sourcing burden;
- monetization/purchase intent (secondary, never above usefulness).

The product should expand by **relationships**, not by unrelated high-volume keywords.
